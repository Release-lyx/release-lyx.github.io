CSS 知识总结（含网安视角）

适配黑马前端课程，搭配上面HTML笔记，可直接粘贴Obsidian CSS：层叠样式表，负责给HTML骨架设置外观、布局、颜色、位置；网安中常用来隐藏内容、构造点击劫持、CSS注入、找页面隐藏flag

一、CSS基础概念

  1. CSS全称：Cascading Style Sheets 层叠样式表
  2. 三大引入方式
  • 行内样式：写在标签style属性里，优先级最高，不推荐维护
  • 内部样式（当前作业常用）：head标签内写<style>标签
  • 外部样式：单独.css文件，link标签引入，项目正式开发使用

🛡️网安要点：外部css文件可以单独被访问，部分源码会把提示、隐藏内容写在css内；css文件不会被浏览器当做脚本执行，但是可以用来探测页面元素、判断元素是否存在

  1. 语法格式
  1. 层叠（优先级）规则 优先级从低到高： 通配符选择器 < 标签选择器 < 类选择器 < 行内样式 < !important（最高，慎用）

    相同优先级，后面写的样式覆盖前面的

🛡️网安要点：开发经常用!important强制样式，审计时看元素样式，开发者工具里划掉的样式就是被更高优先级覆盖的；有些隐藏flag靠高优先级样式遮挡

二、常用选择器（已经学到的）

  1. 通配符选择器 *

作用：选中页面所有标签，统一清除默认边距，布局必备 2. 标签选择器：div、li、p，选中页面全部对应标签 3. 类选择器 .类名

html使用：<div class="box"></div> 特点：一个标签可以多个class；最常用布局选择器 4. 后代选择器（空格隔开）：.box div，选中box里面所有div

🛡️网安要点：css选择器可以定位页面里特定元素，早期CSS注入漏洞可以利用选择器读取页面敏感内容

三、基础文字、颜色、背景样式

  1. 文字样式
  • color：文字颜色（支持英文、十六进制#fff、rgb/rgba）
  • font-size：字号，单位px
  • font-weight：加粗，bold加粗，normal正常
  • text-align：文字对齐 left/center/right
  • text-decoration：none 去掉下划线（a标签常用）
  1. 背景
  • background-color：背景色
  • background-image：背景图片
  • background-repeat：是否平铺 repeat/no-repeat
  1. 颜色表示 十六进制：#ddd、#ffffff rgb：rgb(255,0,0) rgba：多一个透明度参数，rgba(0,0,0,0.5)

🛡️网安要点：rgba透明度、display、visibility是隐藏内容的常用手段；很多CTF题目把flag放在页面，用css隐藏，肉眼看不见，源码存在

四、盒模型（核心重点）

组成：content内容区 + padding内边距 + border边框 + margin外边距 两种模式

  1. content-box（默认）：width只代表内容宽度，padding、border会撑大盒子，布局容易错乱
  2. border-box（布局必写）：width包含内容、padding、border，不会撑大盒子
  • padding：内边距，盒子内部和边框之间距离，padding:上下 左右
  • border：边框 border:1px solid #ddd; 粗细 线型 颜色
  • margin：外边距，盒子和外部其他盒子距离
    • margin:0 auto; 块级盒子水平居中（高频！只对块级生效，行内无效）

      🛡️网安要点：利用margin负边距、定位偏移，可以把文字移出可视窗口，实现隐藏内容；浏览器开发者工具Computed面板可以查看盒子真实尺寸

五、元素显示模式（和HTML标签对应）

  1. block块级：独占一行，可设置宽高 div h1 p ul
  2. inline行内：不独占一行，不能直接设置宽高 span a strong
  3. inline-block行内块：并排，可以设置宽高 img input button 修改显示模式：display:block / display:inline-block / display:none
  • display:none：元素直接消失，不占页面空间
  • visibility:hidden：元素看不见，但是位置还保留，占用空间

    🛡️网安高频考点： display:none 隐藏元素，F12源码里依然存在；很多CTF题目flag写在display:none标签内； 区分：display:none = 消失不占位；visibility:hidden = 看不见，占位

六、Flex弹性布局（你刚练完抖音方案板块）

开启flex：给父盒子写 display:flex; 核心概念：主轴、侧轴（交叉轴） 默认主轴水平从左到右，侧轴垂直从上到下

父容器属性（写在父盒子）

  1. flex-direction：修改主轴方向 row（默认，水平左→右）、row-reverse、column（垂直上→下）、column-reverse
  2. flex-wrap：是否换行 nowrap（默认，不换行，盒子被挤压）、wrap（空间不足自动换行，作业高频）、wrap-reverse
  3. justify-content：主轴对齐 flex-start靠左、flex-end靠右、center居中 space-between：两端贴边，中间空隙均分（抖音卡片布局） space-around：两侧留白，两端空隙是中间一半 space-evenly：全部空隙大小一致
  4. align-items：单行侧轴对齐（没有换行时使用） flex-start靠上、flex-end靠下、center垂直居中、stretch默认拉伸
  5. align-content：多行侧轴对齐，必须配合flex-wrap:wrap换行才生效，单行无效 取值和justify-content一致，控制多行整体分布

子元素属性（写在子盒子）

  1. flex:1; 平分父盒子剩余空间，自适应均分宽度
  2. order:数字，调整排序，数字越小越靠前，默认0，不改HTML调换顺序
  3. align-self：单独控制某一个子盒子侧轴对齐，不和其他子元素保持一致

万能flex模板

  1. 盒子内部内容水平+垂直居中
  1. 一行卡片，两端对齐，屏幕小自动换行

🛡️网安要点：flex布局只是排版，不会改变DOM源码顺序；页面视觉顺序和源码顺序不一致是常见坑，看源码不要只看页面视觉；CSS注入可以搭配flex做元素探测

七、定位 position（了解，后续会练）

  • static 默认静态定位，正常文档流
  • relative 相对定位：相对于自己原本位置偏移，保留原来位置
  • absolute 绝对定位：相对于最近有定位的父盒子，脱离文档流，不占位
  • fixed 固定定位：相对于浏览器窗口固定，滚动页面不动 偏移属性：top left right bottom

    🛡️网安重点：点击劫持（ClickJacking）核心原理！ 透明绝对定位iframe盖在正常页面上方，诱导用户点击，看起来点的是正常按钮，实际是点击了iframe内恶意页面。防御：X-Frame-Options响应头，禁止页面被iframe嵌套

八、伪类（常用）

常用伪类：hover鼠标悬浮、active点击瞬间、link未访问、visited访问过后

🛡️网安：hover、visited伪类早期被用来探测用户访问历史，现在浏览器已经做防护

九、网安专项CSS知识点（CTF、Web审计重点）

  1. CSS隐藏flag的几种方式（做题高频）
  • display:none; 隐藏，不占位
  • visibility:hidden; 隐藏，占位
  • opacity:0; 透明度0，看不见，元素可交互
  • position定位偏移，left:-9999px; 移出屏幕可视区域
  • 文字颜色和背景色一模一样 color:#fff;background:#fff;

    这类隐藏，页面肉眼看不到，但是HTML源码存在，F12元素面板直接抓到

  1. CSS注入（CSS Injection） 前提：可控输入可以拼入CSS代码中 危害：早期可利用选择器、属性读取页面敏感数据；现代浏览器限制比较多，难度高于XSS，CTF小众考点
  2. 点击劫持 ClickJacking CSS绝对定位+透明iframe，防御：后端返回X-Frame-Options: DENY
  3. 样式绕过前端限制 前端用css限制大小、外观，全部可以F12修改，不能当做安全校验，安全校验必须后端
  4. @import 引入外部css，审计时可以追踪import引入的外部资源，排查外链

十、CSS易错踩坑清单

  1. 符号全部英文半角，中文分号、冒号直接失效
  2. 类选择器css里面写.，html class属性不加.
  3. flex区分：align-items单行；align-content多行（wrap换行才生效）
  4. margin:0 auto 只对块级元素生效，行内span、a无效
  5. 忘记box-sizing:border-box，padding、border撑大盒子布局错乱
  6. display:none 和 visibility:hidden 分不清
  7. flex默认不换行，想要换行必须加 flex-wrap:wrap;
  8. !important优先级极高，不要随便写，排查样式问题最后看它

十一、速记口诀

CSS改样式，三法引入； 选择器有优先级，通配最低行内高； 盒模型分两种，border-box是首选； flex父开display，主轴justify，单行align-items； css能藏内容，肉眼看不见源码留； 前端样式随便改，安全校验放后端。

CSS复合选择器与隐藏元素

CSS 复合选择器（Web安全前端基础）

用途：看懂网页源码、CTF隐藏页面、钓鱼页面审计

1. 后代选择器（空格）

.box span
匹配 box 里面所有 span（儿子、孙子都算）

2. 子代选择器（>）

.box > span
只匹配 box 的直接子元素（亲儿子）

3. 并集选择器（逗号 ,）

h3 , .txt
同时选中 h3 和 class=txt

4. 交集选择器（紧贴，无空格）

div.red
同时满足：是 div，并且 class 为 red

隐藏元素（网安高频考点）

  1. display: none
    元素从布局移除，不占位置，肉眼看不见，源码还在。
  2. visibility: hidden
    元素保留占位，只是看不见。
  3. opacity:0
    完全透明，占位，还能点击。

网安场景：flag、隐藏提示、钓鱼页面隐藏内容

Flex 布局速记笔记

核心：给父盒子加 display: flex;，控制子元素的排列，分为【主轴】和【侧轴（交叉轴）】 默认：主轴=水平（从左→右），侧轴=垂直（从上→下）

一、父容器（加在父盒子上）

1. flex-direction 👉 修改主轴方向

2. flex-wrap 👉 是否换行（重点！）

3. justify-content 👉 主轴对齐（最常用）

4. align-items 👉 侧轴对齐（单行的时候用！）

单行、没有换行，用这个

5. align-content 👉 多行侧轴对齐（⚠️必须配合 wrap 换行！）

只有子元素换行了、出现多行，这条才生效！单行无效

二、子元素属性（写在子div上）

1. flex 弹性伸缩（简写）

flex: 1; 👉 平分剩余空间，自适应宽度（卡片均分神器）

  • flex-grow：放大比例，默认0，有多余空间才放大
  • flex-shrink：缩小比例，默认1，空间不够会缩小
  • flex-basis：基础宽度，默认auto

2. align-self 👉 单独控制某一个子盒子侧轴对齐

可以不和其他子盒子保持一致，单独设置

3. order 👉 排序

order: 数字; 默认0，数字越小，排得越靠前（可以不改HTML，调换顺序）

三、高频组合模板（直接抄作业）

  1. 水平+垂直居中（万能居中）
  1. 一行多个盒子，左右贴边，中间自动空隙（抖音方案板块）
  1. 垂直方向排列、居中

四、易错踩坑清单（你之前踩过的！）

  1. ✅ justify-content 管主轴；align-items 管单行侧轴；align-content 只管多行（wrap换行后）
  2. ✅ flex 布局子元素默认不换行，想换行一定要加 flex-wrap: wrap;
  3. ✅ 父盒子写 display:flex，属性是给父的；flex:1、order 这些是给子盒子
  4. ✅ 通配符重置样式别漏 *
  1. ✅ 标签class要对应，写了.box样式，body里必须有 <div class="box">，不然看不到盒子

五、一句话速记口诀

父开flex，定主轴，主轴justify，单行align-items，多行align-content； 子元素flex用来分空间，order调顺序，align-self单独改。

HTML 知识总结（网安视角）

HTML 知识总结（含网安视角）

适用：黑马前端课程 HTML 阶段 + 网安/CTF Web 方向 定位：前端做页面用 HTML 搭骨架；网安看页面源码、找漏洞也靠它

一、HTML 是什么

  • HTML = 超文本标记语言，不是编程语言，只是用“标签”把内容包起来
  • 网页三件套：
    • HTML：骨架（有哪些内容）
    • CSS：皮肤（长什么样）
    • JavaScript：肌肉（能做什么交互）
  • 浏览器做事的两步：
    1. 先拿到 HTML 文本（源码）
    2. 再按标签规则渲染成页面（你看到的样子）

🛡️ 网安要点：你在页面上看到的 ≠ 源码里的全部内容。被隐藏、被注释、在属性里的东西，浏览器不一定显示，但源码里都在。CTF Web 题第一步永远是“看源码”。

二、标准骨架（输入 ! + Tab 一键生成）

逐行解释：

行 作用 记法
<!DOCTYPE html> 声明这是 HTML5 文档，必须第一行 不写会进入怪异模式，样式可能错乱
<html> 整个网页的根标签 一个页面只有一个
<head> 配置区，页面看不见 编码、标题、引入 CSS 都写这里
<meta charset="UTF-8"> 设置文字编码，防中文乱码 必须写，写错中文变乱码
<meta name="viewport"> 移动端适配 做手机端页面必备
<title> 浏览器标签页上的标题 搜索引擎、收藏夹用的就是它
<body> 页面上看得见的所有内容 布局都在这写

🛡️ 网安要点：<title> 和 <meta> 会被搜索引擎、爬虫抓走；有人会在 meta 里塞隐藏提示（CTF 常见）。robots.txt、sitemap 常和这些配置一起被用来做信息收集。

三、注释

  • 快捷键：VS Code 里 Ctrl + /
  • 注释不会被渲染，但会原样出现在源码里

🛡️ 网安要点（高频考点）：开发者习惯把测试账号、内网地址、接口路径、TODO、备份文件名写在注释里，忘了删。

  • CTF 里常见：注释里藏 flag、藏下一步的路径、藏提示
  • 真实站点：注释泄露后台地址、数据库名、内部接口
  • 位置：Ctrl + U 看源码后，搜 <!--，或在开发者工具 Elements 面板里看灰色内容
  • 防御角度：上线前统一清理注释，敏感配置放服务端，不写在前端

四、标签分类（最重要的一张表）

类型 代表标签 特点 能否设宽高
块级元素 div h1~h6 p ul li table 独占一行，宽度默认撑满父盒子 ✅ 能
行内元素 span a strong em 不独占一行，多个能并排 ❌ 不能（设了也不生效）
行内块元素 img input button 不独占一行，但能设宽高 ✅ 能

记法：

  • 要“占一整行、能当容器” → div
  • 要“给一小段文字单独上色/加样式” → span
  • 常见坑：给 span 写 width:200px; 没反应，就是因为它不能设宽高

🛡️ 网安要点：div 套 div、span 套 span 的结构，是看页面结构时最常打交道的。开发者工具的 Elements 面板就是一棵标签树，能一层层展开，是前端审计、找隐藏节点的主要工具。

五、文本类标签

  • <h1> 一个页面只写一个，是 SEO 权重最高的标题
  • strong / em 有“语义”（表示重要/强调），b / i 只有外观，考试常考区别

🛡️ 网安要点：<h1> 里的关键词会被搜索引擎重点抓取，这是 SEO 层面的东西；而 <strong> 这类“有语义”的标签，正是前端代码规范审计时会看的东西——不同团队规范不同，审计报告里会写“语义化是否规范”。

六、特殊字符（HTML 实体）

有些符号在 HTML 里有特殊含义，必须“转义”才能显示：

想显示 写什么 说明
< &lt; 小于号是标签的开始，必须转义
> &gt; 大于号
& &amp; 与号
空格（连续多个） &nbsp; 普通空格会被合并成一个
版权 &copy; ©

🛡️ 网安要点（XSS 的根）：浏览器看到 < 会当成标签开始，看到 &lt; 只会当成普通文字。

  • 后端把用户输入原样拼进 HTML 时，如果输入里的 <script> 没被转义，浏览器就会真的执行它——这就是 XSS（跨站脚本） 的核心原理
  • 防御：输出到页面时做 HTML 实体编码（< → &lt;），输入侧做过滤
  • 判断点：一个页面把用户输入回显出来，就是潜在 XSS 点（搜索框回显、留言板、个人昵称、URL 参数）
  • 考试常问：&lt;script&gt; 会不会执行？答案：不会，它只是文字

七、图片标签

  • 单标签，不需要闭合
  • src：图片地址（本地路径 / 网址都行）
  • alt：图挂了显示的文字，也是搜索引擎读图依据
  • 宽高一般用 CSS 设，不要写死

🛡️ 网安要点：

  • alt 和文件名会泄露信息（比如 admin后台截图.png），信息收集时图片名也在收集范围里
  • <img src> 能发起外部请求，所以历史上被用来做“图片探测”和 CSRF 辅助（加载即请求）
  • 防御角度：图片走独立域名/图床、文件名重命名去语义化

八、超链接

  • target="_blank"：新窗口打开
  • #：占位链接，还没想好跳哪时用

🛡️ 网安要点：

  • javascript: 伪协议可以在链接里塞脚本，属于 XSS 的一种入口（防御：白名单校验 href）
  • target="_blank" 老版本有 window.opener 劫持问题（防御：加 rel="noopener noreferrer"）
  • 钓鱼类题里，链接文字和真实 href 不一致是常见陷阱：永远看 href，不看文字

九、列表

去掉前面小圆点：

  • 实际开发里，导航栏、卡片列表都是 ul > li 结构（不是纯 div）

🛡️ 网安要点：后台菜单、权限入口常见 ul > li；题目给你一个“用户菜单”，管理员那一项可能是被隐藏的 li（display:none 或注释掉），点不开但源码在。

十、表格

  • table 表格 / tr 行 / th 表头单元格 / td 普通单元格
  • 合并单元格：colspan（跨列）、rowspan（跨行）
  • 现在页面布局不用表格了（老网页才用），但表格标签本身还在用（数据展示）

🛡️ 网安要点：老站点（政府、企业后台）大量用 table 布局，这类站点的 HTML 结构往往很乱、注释多、参数命名随意，审计时反而容易找到问题。看到 table 布局基本能判断站点较老。

十一、表单（网安最重要的一节）

表单就是“用户填东西、提交给服务器”的容器。

属性 作用 网安意义
action 数据提交给哪个地址 直接暴露后端接口路径
method 提交方式 get / post 决定参数在 URL 还是请求体里

11.1 输入框

  • name 必须有，没有 name 后端收不到这个值
  • type="password" 只是显示成圆点，不代表加密

11.2 单选 / 多选

  • value 才是真正提交上去的值，页面上写的“男/女”只是给人看的

11.3 文件上传

  • **必须写 enctype="multipart/form-data"**，不写文件传不上去

🛡️ 网安要点（文件上传漏洞）：

  • 上传点是最经典的高危入口之一，核心问题是“服务端有没有校验类型/后缀/内容”
  • 防御三件套：白名单校验后缀、校验文件真实类型（不看 Content-Type，看文件头）、上传目录不能解析执行脚本、文件重命名
  • 学习顺序上，这个知识点等学到文件上传漏洞再深入，现在先记住“看到 file 表单就要多看一眼”

11.4 下拉框 / 文本域

11.5 按钮

11.6 label（点文字也能选中输入框）

  • label 的 for 要等于 input 的 id

🔑 表单里网安必记的 5 个点

  1. name 属性 = 后端参数名。抓包看到的 username=xxx&password=xxx，对应的就是这两个 name
  2. GET vs POST：
    • GET：参数拼在 URL 上，?a=1&b=2，能被看到、被记录在日志、能直接改 URL 试
    • POST：参数在请求体里，URL 上看不到，要用抓包工具看
    • 注意：POST 只是“不显示在 URL”，不加密、不防篡改，抓包一样能改
  3. **隐藏字段 type="hidden"**：
    • 页面上看不见，但会提交
    • 如果后端直接信这个值，把 value 改成 admin 就能越权——这是最经典的越权/水平垂直越权考点
  4. 前端校验不等于安全：maxlength、required、JS 校验都能绕过（改源码、抓包重发）。所有校验必须在服务端再做一遍
  5. action 泄露接口：很多站点的真实接口就写在 form 的 action 里，比猜路径快得多

十二、语义化标签（HTML5 新增）

  • 作用和 div 一样，只是名字有意义，方便人和搜索引擎理解
  • 黑马课程里“网页项目”部分：header / banner / footer 就是这么分区的

十三、🛡️ 网安视角总汇总（这一节单独背）

1. 拿到一个网页，按这个顺序看

  1. Ctrl + U（或右键“查看源代码”）→ 看原始源码，能看注释
  2. F12 → Elements 面板 → 看渲染后的结构，能看到被 JS 改过的内容
  3. 差异很重要：源码里有但页面没显示 = 隐藏内容；源码里没有但页面有 = JS 生成的

2. HTML 层面常见的信息泄露点

位置 泄露什么
注释 <!-- --> 测试账号、内网地址、备份路径、TODO、flag
type="hidden" 权限标记、价格、用户 id —— 可篡改
form action 后端接口路径、参数格式
meta 标签 框架版本、隐藏提示
标签属性（data-*、id、class） 业务含义、内部命名、接口暗示
图片文件名 / alt 内部系统截图、后台名字
被注释掉的整块代码 废弃但可能还能访问的接口

3. 和 HTML 直接相关的漏洞类型

  • XSS（跨站脚本）：用户输入没转义就被当标签执行。HTML 视角看，就是 < 没变成 &lt;
  • CSRF（跨站请求伪造）：借你已登录的身份，自动提交一个表单/请求。form 的自动提交能力就是基础
  • 点击劫持：用透明层盖住页面骗你点击，和 CSS 的 opacity / 定位强相关
  • 越权：篡改 hidden 字段或参数值，拿到不该有的权限
  • 文件上传：enctype="multipart/form-data" 的表单是入口
  • 信息泄露：注释、meta、action 把内部信息拱手送出

4. 一句话原则

前端的一切都能被看到、被修改。所以：前端只负责体验，安全校验必须在服务端。

十四、易错踩坑清单

  1. 标签忘记闭合：<div> 写了没写 </div>，后面全乱套
  2. 中文符号：；、（）、“” 混进代码 → 直接失效
  3. <img> <br> <hr> <input> 是单标签，不要写成 </img>
  4. name 忘了写 → 表单提交后端收不到值
  5. 文件上传忘了 enctype="multipart/form-data"
  6. 一个页面写了多个 <h1>
  7. class 属性不加点，CSS 里 .box 才加点
  8. <title> 忘了写，标签页显示成路径
  9. 编码不是 UTF-8，中文乱码

十五、速记口诀

DOCTYPE 打头，html 包一切；head 放配置，body 放内容。 块级占一行，行内不设宽；img input 是行内块。 注释藏信息，hidden 能篡改，action 露接口。 前端所见皆可改，校验必须在服务端。
