HTML 知识总结（网安视角）

HTML 知识总结（含网安视角）

适用：黑马前端课程 HTML 阶段 + 网安/CTF Web 方向 定位：前端做页面用 HTML 搭骨架；网安看页面源码、找漏洞也靠它

一、HTML 是什么

  • HTML = 超文本标记语言，不是编程语言，只是用“标签”把内容包起来
  • 网页三件套：
    • HTML：骨架（有哪些内容）
    • CSS：皮肤（长什么样）
    • JavaScript：肌肉（能做什么交互）
  • 浏览器做事的两步：
    1. 先拿到 HTML 文本（源码）
    2. 再按标签规则渲染成页面（你看到的样子）

🛡️ 网安要点：你在页面上看到的 ≠ 源码里的全部内容。被隐藏、被注释、在属性里的东西，浏览器不一定显示，但源码里都在。CTF Web 题第一步永远是“看源码”。

二、标准骨架（输入 ! + Tab 一键生成）

逐行解释：

行 作用 记法
<!DOCTYPE html> 声明这是 HTML5 文档，必须第一行 不写会进入怪异模式，样式可能错乱
<html> 整个网页的根标签 一个页面只有一个
<head> 配置区，页面看不见 编码、标题、引入 CSS 都写这里
<meta charset="UTF-8"> 设置文字编码，防中文乱码 必须写，写错中文变乱码
<meta name="viewport"> 移动端适配 做手机端页面必备
<title> 浏览器标签页上的标题 搜索引擎、收藏夹用的就是它
<body> 页面上看得见的所有内容 布局都在这写

🛡️ 网安要点：<title> 和 <meta> 会被搜索引擎、爬虫抓走；有人会在 meta 里塞隐藏提示（CTF 常见）。robots.txt、sitemap 常和这些配置一起被用来做信息收集。

三、注释

  • 快捷键：VS Code 里 Ctrl + /
  • 注释不会被渲染，但会原样出现在源码里

🛡️ 网安要点（高频考点）：开发者习惯把测试账号、内网地址、接口路径、TODO、备份文件名写在注释里，忘了删。

  • CTF 里常见：注释里藏 flag、藏下一步的路径、藏提示
  • 真实站点：注释泄露后台地址、数据库名、内部接口
  • 位置：Ctrl + U 看源码后，搜 <!--，或在开发者工具 Elements 面板里看灰色内容
  • 防御角度：上线前统一清理注释，敏感配置放服务端，不写在前端

四、标签分类（最重要的一张表）

类型 代表标签 特点 能否设宽高
块级元素 div h1~h6 p ul li table 独占一行，宽度默认撑满父盒子 ✅ 能
行内元素 span a strong em 不独占一行，多个能并排 ❌ 不能（设了也不生效）
行内块元素 img input button 不独占一行，但能设宽高 ✅ 能

记法：

  • 要“占一整行、能当容器” → div
  • 要“给一小段文字单独上色/加样式” → span
  • 常见坑：给 span 写 width:200px; 没反应，就是因为它不能设宽高

🛡️ 网安要点：div 套 div、span 套 span 的结构，是看页面结构时最常打交道的。开发者工具的 Elements 面板就是一棵标签树，能一层层展开，是前端审计、找隐藏节点的主要工具。

五、文本类标签

  • <h1> 一个页面只写一个，是 SEO 权重最高的标题
  • strong / em 有“语义”（表示重要/强调），b / i 只有外观，考试常考区别

🛡️ 网安要点：<h1> 里的关键词会被搜索引擎重点抓取，这是 SEO 层面的东西；而 <strong> 这类“有语义”的标签，正是前端代码规范审计时会看的东西——不同团队规范不同，审计报告里会写“语义化是否规范”。

六、特殊字符（HTML 实体）

有些符号在 HTML 里有特殊含义，必须“转义”才能显示：

想显示 写什么 说明
< &lt; 小于号是标签的开始，必须转义
> &gt; 大于号
& &amp; 与号
空格（连续多个） &nbsp; 普通空格会被合并成一个
版权 &copy; ©

🛡️ 网安要点（XSS 的根）：浏览器看到 < 会当成标签开始，看到 &lt; 只会当成普通文字。

  • 后端把用户输入原样拼进 HTML 时，如果输入里的 <script> 没被转义，浏览器就会真的执行它——这就是 XSS（跨站脚本） 的核心原理
  • 防御：输出到页面时做 HTML 实体编码（< → &lt;），输入侧做过滤
  • 判断点：一个页面把用户输入回显出来，就是潜在 XSS 点（搜索框回显、留言板、个人昵称、URL 参数）
  • 考试常问：&lt;script&gt; 会不会执行？答案：不会，它只是文字

七、图片标签

  • 单标签，不需要闭合
  • src：图片地址（本地路径 / 网址都行）
  • alt：图挂了显示的文字，也是搜索引擎读图依据
  • 宽高一般用 CSS 设，不要写死

🛡️ 网安要点：

  • alt 和文件名会泄露信息（比如 admin后台截图.png），信息收集时图片名也在收集范围里
  • <img src> 能发起外部请求，所以历史上被用来做“图片探测”和 CSRF 辅助（加载即请求）
  • 防御角度：图片走独立域名/图床、文件名重命名去语义化

八、超链接

  • target="_blank"：新窗口打开
  • #：占位链接，还没想好跳哪时用

🛡️ 网安要点：

  • javascript: 伪协议可以在链接里塞脚本，属于 XSS 的一种入口（防御：白名单校验 href）
  • target="_blank" 老版本有 window.opener 劫持问题（防御：加 rel="noopener noreferrer"）
  • 钓鱼类题里，链接文字和真实 href 不一致是常见陷阱：永远看 href，不看文字

九、列表

去掉前面小圆点：

  • 实际开发里，导航栏、卡片列表都是 ul > li 结构（不是纯 div）

🛡️ 网安要点：后台菜单、权限入口常见 ul > li；题目给你一个“用户菜单”，管理员那一项可能是被隐藏的 li（display:none 或注释掉），点不开但源码在。

十、表格

  • table 表格 / tr 行 / th 表头单元格 / td 普通单元格
  • 合并单元格：colspan（跨列）、rowspan（跨行）
  • 现在页面布局不用表格了（老网页才用），但表格标签本身还在用（数据展示）

🛡️ 网安要点：老站点（政府、企业后台）大量用 table 布局，这类站点的 HTML 结构往往很乱、注释多、参数命名随意，审计时反而容易找到问题。看到 table 布局基本能判断站点较老。

十一、表单（网安最重要的一节）

表单就是“用户填东西、提交给服务器”的容器。

属性 作用 网安意义
action 数据提交给哪个地址 直接暴露后端接口路径
method 提交方式 get / post 决定参数在 URL 还是请求体里

11.1 输入框

  • name 必须有，没有 name 后端收不到这个值
  • type="password" 只是显示成圆点，不代表加密

11.2 单选 / 多选

  • value 才是真正提交上去的值，页面上写的“男/女”只是给人看的

11.3 文件上传

  • **必须写 enctype="multipart/form-data"**，不写文件传不上去

🛡️ 网安要点（文件上传漏洞）：

  • 上传点是最经典的高危入口之一，核心问题是“服务端有没有校验类型/后缀/内容”
  • 防御三件套：白名单校验后缀、校验文件真实类型（不看 Content-Type，看文件头）、上传目录不能解析执行脚本、文件重命名
  • 学习顺序上，这个知识点等学到文件上传漏洞再深入，现在先记住“看到 file 表单就要多看一眼”

11.4 下拉框 / 文本域

11.5 按钮

11.6 label（点文字也能选中输入框）

  • label 的 for 要等于 input 的 id

🔑 表单里网安必记的 5 个点

  1. name 属性 = 后端参数名。抓包看到的 username=xxx&password=xxx，对应的就是这两个 name
  2. GET vs POST：
    • GET：参数拼在 URL 上，?a=1&b=2，能被看到、被记录在日志、能直接改 URL 试
    • POST：参数在请求体里，URL 上看不到，要用抓包工具看
    • 注意：POST 只是“不显示在 URL”，不加密、不防篡改，抓包一样能改
  3. **隐藏字段 type="hidden"**：
    • 页面上看不见，但会提交
    • 如果后端直接信这个值，把 value 改成 admin 就能越权——这是最经典的越权/水平垂直越权考点
  4. 前端校验不等于安全：maxlength、required、JS 校验都能绕过（改源码、抓包重发）。所有校验必须在服务端再做一遍
  5. action 泄露接口：很多站点的真实接口就写在 form 的 action 里，比猜路径快得多

十二、语义化标签（HTML5 新增）

  • 作用和 div 一样，只是名字有意义，方便人和搜索引擎理解
  • 黑马课程里“网页项目”部分：header / banner / footer 就是这么分区的

十三、🛡️ 网安视角总汇总（这一节单独背）

1. 拿到一个网页，按这个顺序看

  1. Ctrl + U（或右键“查看源代码”）→ 看原始源码，能看注释
  2. F12 → Elements 面板 → 看渲染后的结构，能看到被 JS 改过的内容
  3. 差异很重要：源码里有但页面没显示 = 隐藏内容；源码里没有但页面有 = JS 生成的

2. HTML 层面常见的信息泄露点

位置 泄露什么
注释 <!-- --> 测试账号、内网地址、备份路径、TODO、flag
type="hidden" 权限标记、价格、用户 id —— 可篡改
form action 后端接口路径、参数格式
meta 标签 框架版本、隐藏提示
标签属性（data-*、id、class） 业务含义、内部命名、接口暗示
图片文件名 / alt 内部系统截图、后台名字
被注释掉的整块代码 废弃但可能还能访问的接口

3. 和 HTML 直接相关的漏洞类型

  • XSS（跨站脚本）：用户输入没转义就被当标签执行。HTML 视角看，就是 < 没变成 &lt;
  • CSRF（跨站请求伪造）：借你已登录的身份，自动提交一个表单/请求。form 的自动提交能力就是基础
  • 点击劫持：用透明层盖住页面骗你点击，和 CSS 的 opacity / 定位强相关
  • 越权：篡改 hidden 字段或参数值，拿到不该有的权限
  • 文件上传：enctype="multipart/form-data" 的表单是入口
  • 信息泄露：注释、meta、action 把内部信息拱手送出

4. 一句话原则

前端的一切都能被看到、被修改。所以：前端只负责体验，安全校验必须在服务端。

十四、易错踩坑清单

  1. 标签忘记闭合：<div> 写了没写 </div>，后面全乱套
  2. 中文符号：；、（）、“” 混进代码 → 直接失效
  3. <img> <br> <hr> <input> 是单标签，不要写成 </img>
  4. name 忘了写 → 表单提交后端收不到值
  5. 文件上传忘了 enctype="multipart/form-data"
  6. 一个页面写了多个 <h1>
  7. class 属性不加点，CSS 里 .box 才加点
  8. <title> 忘了写，标签页显示成路径
  9. 编码不是 UTF-8，中文乱码

十五、速记口诀

DOCTYPE 打头，html 包一切；head 放配置，body 放内容。 块级占一行，行内不设宽；img input 是行内块。 注释藏信息，hidden 能篡改，action 露接口。 前端所见皆可改，校验必须在服务端。
