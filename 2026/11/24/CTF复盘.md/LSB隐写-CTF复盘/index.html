CTF复盘｜RGB联合LSB隐写（二维码坑点总结）

题目类型

MISC｜RGB三通道联合LSB隐写 + 残缺二维码

✅ 正确提取参数（你全部选对了）

  • 通道：Red + Green + Blue
  • 提取位：Bit0（最低位LSB）
  • 扫描顺序：Row（按行）
  • Bit顺序：LSB first
  • 交织模式：RGB

🎯 预期结果

提取出来的比特流本质就是一张完整的正方形二维码，三个角落都有定位方块，扫码直接得到flag。

🧩 卡关核心原因（最关键考点）

网上早年的Writeup，选手使用的是本地Java原版 StegSolve.jar

原版特点：预览、保存图片时，会按照真实像素数量渲染，不会乱改图片宽高，直接得到完整二维码

👉 你使用的网页复刻版工具存在缺陷

  1. 导出图片时自动生成PNG，IHDR高度字段被写小 → 图片下半部分被截断，右下角二维码定位方块消失，无法识别
  2. 尝试下载Raw原始二进制数据时，数据量大导致浏览器内存溢出，页面直接崩溃

✅ 两种可行的完整解法（以后环境合适可以回来复现）

  1. 本地环境：安装Java，运行原版 StegSolve.jar，参数相同，直接预览完整二维码
  2. 脚本方案：成功下载Raw字节流后，用Python手动指定正方形宽高，重新渲染图片，避开错误PNG头

💡 学到的经验

  1. LSB隐写，支持多通道（R+G+B）联合提取比特
  2. ⚠️ 非常重要：网页版工具 ≠ 原版StegSolve，导出图像行为会有差异，很容易出现截断、文件损坏等诡异bug
  3. 二维码识别的必要条件：必须集齐3个角落的定位方块，缺一个就会识别失败

这道题完整复盘笔记（直接归档）

题目考点

  • 类型：MISC 图像隐写，RGB 三通道联合 LSB 隐写
  • 提取参数：R、G、B 三个通道的最低位 Bit0；扫描顺序 Row；LSB‑first；交织 RGB

坑点（就是卡你的地方）

  1. 老 writeup 全部基于本地 Java 版 StegSolve，预览 / 保存不会截断图像
  2. 现在的网页复现工具存在 bug：导出 PNG 时自动写入错误的 IHDR 高度，图片截断，右下角二维码定位块消失，无法扫码
  3. 尝试下载 Raw 原始字节流的时候，数据量过大，浏览器内存爆满 → 页面直接崩溃加载失败

两种正确解法（以后环境到位可以回来复现拿 flag）

  1. 本地运行原版 StegSolve.jar（需要 Java 环境），提取之后直接预览，完整二维码直接扫码
  2. 拿到 Raw bytes 原始数据流，用 Python 手动指定正方形宽高，重新渲染图片，绕开自动生成的坏 PNG 头
